# Source prior, LCBench-only confirmation: plan v1 for approval (2026-10-31)

Status: DRAFT, nothing run. Follows `PLAN_source_prior.md` (v2), whose T1 stop rule fired (SP worse than W1 on TabRepo in all 9 configs), and the exploratory diagnostic `meta/results/sp_diag.txt`.

## 1. Why this plan exists, and what it is not
The diagnostic (6 LCBench tuning landscapes, 2 seeds) showed the prior mean helping on LCBench (selected SP, c = 0.25: -24.6 % AUC vs W1; uniform weights: -3.9 %) and hurting on TabRepo (+4.2 % to +23.5 %). That reading was formed **after** the stop rule fired and after looking at several variants, so it is a hypothesis generated by tuning-set data, not a finding. This plan tests it on landscapes and seeds that played no part in the diagnostic. The original plan's TabRepo and noise branches stay closed (TabRepo) or deferred (noise).

Scope of any claim from this plan: **LCBench-like landscapes only** (shared grid, 29 or so sources, learning-curve HPO). It cannot rescue the general source-prior claim.

## 2. Question
On held-out LCBench landscapes, does a similarity-weighted source prior (a) beat the portfolio start with a standard GP (W1), (b) do so because of the weighting, and (c) because the weights are updated during the campaign rather than fixed once?

## 3. Method (frozen now, no re-tuning)
Implementation is the existing `meta/sp.py` (`run_sp`), unchanged. Same initial design as W1 (greedy portfolio from the other LCBench tasks, held-out task excluded), same engine, budget rule and metric.
- **Primary configuration: kappa = 10, lambda = 0.25, c = 0.25.** kappa and lambda come from the original T1 selection (`sp_selected.json`). c = 0.25 comes from the diagnostic: it is the value that limited TabRepo harm (+4.2 % vs +23.5 % at c = 0) while keeping the LCBench gain. It is chosen post hoc on 6 landscapes; the selection bias is stated, and c = 0 is run as a pre-declared sensitivity arm (reported, not gated).
- Nothing else is varied. If the result is borderline, no re-tuning on the test landscapes.

## 4. Arms (same landscapes, seeds and initial design)
| Arm | What it tests |
|---|---|
| random | random start + standard GP (reference for failure cases) |
| W1 | portfolio start + standard GP (baseline to beat) |
| SP | weights recomputed every step (the method), c = 0.25 |
| SP-frozen | weights fixed after the n0 initial observations, c = 0.25 (reactivity) |
| SP-uniform | equal weights, same prior mean and variance term, c = 0.25 (weighting) |
| SP-shuffled | each source's scores permuted over configs, then the method (prior adds nothing) |
| SP-permw | SP weights at step n0 permuted over sources, then fixed (weight information vs weight volatility) |
| SP-c0 | SP with c = 0 (sensitivity, not gated) |

Eight arms x 24 landscapes x 4 seeds = 768 campaigns; estimated 30 to 40 minutes on 12 workers (to be confirmed by a 1-landscape timing run before the full run).

## 5. Data and seeds
- Landscapes: the **24 LCBench dev landscapes in w150 that are not in `sp_tuning_set.json`**. Reserved LCBench (`splits.CONFIRM`), FCNet, NAS-Bench-201 untouched.
- Seeds **4700-4703**, noise 0. Not used by any earlier block (tuning 4500-4501, T1 detection 4300-4311, unrun test block 4600-4603 left unused).
- No TabRepo run. The known TabRepo harm (tuning set, 36 landscapes: +4.2 % at c = 0.25, +21.5 % at the T1 setting) is reported as a limitation next to every LCBench number.

## 6. Hypotheses and gates (fixed now)
Seed-averaged AUC per landscape; summary = ratio of means over the 24 landscapes (also the mean of per-landscape ratios, reported alongside); paired Wilcoxon over landscapes; Holm correction over the three gated tests.
- **TH-L1 (value):** SP at least **5 %** below W1, p < 0.05. Also reported: share of landscapes where SP is worse than W1 by more than 5 %, and the worst case. If that share exceeds 25 %, TH-L1 is labelled "passes on average, harmful on a sizeable minority".
- **TH-L2 (weighting matters):** SP at least **2 %** below SP-uniform, p < 0.05.
- **TH-L3 (reactivity):** SP at least **2 %** below SP-frozen, p < 0.05.
- **Controls (must hold or the result is void):** SP-shuffled is not more than 2 % better than W1; SP-permw is at least 2 % worse than SP.
- **Failure cases (secondary, descriptive):** landscapes where W1 loses to random on the new seeds by more than 5 % of the random AUC; how much of the excess SP closes. The count is probably small, so there is no gate on it.

## 7. Outcomes and what each would mean
| Result | Reading |
|---|---|
| L1, L2, L3 all pass, controls hold | A reactive similarity-weighted prior pays on LCBench-like landscapes. Still LCBench only; noise (5 %) is the next question, with its own approval |
| L1, L2 pass, L3 fails | A static similarity-weighted prior captures the gain; per-step re-weighting adds nothing. Reactive claim closed, prior claim kept |
| L1 passes, L2 fails | The gain is from using sources as a mean function, not from weighting. Close the weighting claim |
| L1 fails | The diagnostic was selection noise. Source-prior line closed; write up the T1 stop and the diagnostic as a negative result |
| A control fails | Result not interpretable; investigate before any claim |

## 8. Stages (stop and ask at each)
- T0 (engine) is already done under `PLAN_source_prior.md`: `meta/sp.py`, 18 checks in `meta/test_sp.py`, and the b = 0 check in `sp_diag.txt` reproduces W1 exactly. No engine changes here.
- T0b (thin, no test data): write `meta/sp_lcbench.py` (runner) and `meta/analyse_sp_lcbench.py` (the gates above, written **before** any test result exists); 1-landscape timing and a check that the landscape list excludes the tuning set. No test data seen.
- T1: full run, then the analysis script, one pass. No gate edits afterwards; deviations flagged.
- T2 (only if L1 passes, own approval): 5 % observation noise on the same landscapes.
- T3 (only if L1 to L3 pass and a gap remains, own approval): typed Score question over source tasks against the numeric weights (equivalence within 2 %, shuffled-state control). If built, it reads option probabilities from a frozen model's logits instead of generating text.

## 9. Risks
- c = 0.25 and the claim itself come from 6 landscapes; a fresh set may not reproduce them. That is what the test is for.
- LCBench portfolio start leaves room (W1 AUC about 0.19) because those landscapes are harder; a strong effect here says little about settings where the portfolio is already near-optimal, which is what TabRepo showed.
- Best case for transfer (shared grid, many sources). Unchanged from the earlier plans.
- 24 landscapes of one family: a few landscapes can dominate the ratio of means, hence the second summary and the harm share.
